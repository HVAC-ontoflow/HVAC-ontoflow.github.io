개요Overview

무엇으로 만들었는가What it was built from

수도권 복합단지 내 업무시설의 기계 도면(DWG)과 설비 계산서(PDF)를 입력으로, 지상 2층 · 공기측을 범위로 온톨로지를 자동 생성했습니다.
스키마(TBox)는 Brick 1.4.1을 어휘로 재사용하고, 근거 · 출처 · 값의 층위에 관한 문법은 자체 정의했습니다. The ontology was generated automatically from the mechanical drawings (DWG) and equipment calculation sheets (PDF) of an office building in a mixed-use complex in the Seoul metropolitan area, scoped to the second floor, air side. The schema reuses Brick 1.4.1 as a vocabulary; the grammar for evidence, provenance and value layering is defined in-house.

    이 페이지의 모든 수치와 문자열은 실제 자료에서 가져온 것입니다. HVAC 설비 · 값 · 관계 · 출처는 ontology.ttl(ABox), 클래스와 관계 술어는 hvo.ttl(TBox), 질의와 검증된 답변은 CQ 테스트 자료, 구축 규모는 경진대회 포스터에서 확인했습니다.
    화면을 채우기 위해 만들어낸 HVAC 설비나 값은 없습니다.     Every figure and string on this page comes from the actual material. Equipment, values, relations and sources from ontology.ttl (ABox); classes and relation predicates from hvo.ttl (TBox); questions and verified answers from the CQ test document; build statistics from the competition poster. Nothing was invented to fill a panel.

    02

    정보 검증Validation

    믿을 수 있나?Can it be trusted?

    같은 설계정보가 도면과 계산서에 각각 적혀 있을 때, 두 값이 같은지 다른지, 다르다면 허용오차 안인지 실제 모순인지를 값마다 판정해 기록합니다.
    다를 때 시스템이 하나를 고르지 않습니다 — 두 값과 각각의 출처를 그대로 남기고 불일치 자체를 지식으로 보존합니다.     When the same design figure appears in both a drawing and a calculation sheet, each value carries a verdict: do the two agree, and if not, is the gap within tolerance or a real conflict? Where they differ the system does not pick a winner — both values keep their own sources, and the disagreement itself is preserved as knowledge.

    값 노드 4,081개 전수의 검증 상태Verdicts across all 4,081 value nodes

    ontology.ttl 의 hvo:valueStatus 전수 집계.
    다섯 상태의 합이 값 노드 총수와 정확히 일치합니다.     Full count of hvo:valueStatus in ontology.ttl. The five states sum exactly to the total number of value nodes.

      지식 질의Knowledge Query

      검증된 CQ 10문항10 validated CQs

      CQ 테스트에서 검증된 질의와 그 답변입니다.
      답변마다 어떤 트리플에서 나왔고 어느 문서를 가리키는지가 함께 표시되므로, 답을 믿는 대신 근거를 확인할 수 있습니다.
      전체 58문항 중 57문항이 통과(98.3%)했고, 그 가운데 이 연구의 성격을 가장 잘 보여주는 10문항을 실었습니다.       These are the queries and answers verified in the CQ test. Each answer shows which triples it came from and which document it points at, so you can check the evidence rather than trust the answer. 57 of the 58 questions passed (98.3%); the ten shown here are the ones that best characterise the work.

      검증된 질의Validated queries

      통과하지 못한 한 문항. OHUA03의 난방부하를 묻는 질의였습니다.
      계산서에는 0 W와 98,390 W가 함께 있고 정답은 98,390 W였지만, 에이전트는 두 값이 DIVERGENT로 기록되어 있다는 이유로 어느 쪽도 고르지 않고 판단을 보류했습니다.
      틀린 값을 고른 것이 아니라, 고를 수 있는 자리에서 지나치게 조심스러웠던 경우입니다 — 모순을 임의로 해소하지 않는다는 원칙이 필요 이상으로 세게 적용된 셈입니다.       The one question it did not pass asked for OHUA03's heating load. The calculation sheet holds both 0 W and 98,390 W, and 98,390 W was the right answer — but because the two are recorded as DIVERGENT, the agent picked neither and withheld its verdict. It did not choose a wrong value; it was over-cautious where a choice was available, applying the never-resolve-a-contradiction rule harder than the case required.

      자유 질의Free-form query beta

      이 페이지는 시연 안정성을 위해 검증된 CQ 결과를 정적 데이터로 제공합니다.
      자유 질의는 위 10문항의 키워드(예: ZHUA01, 모터동력, 7300, 6201, OHUA03)를 찾아 해당 CQ로 이동시키는 정도만 동작합니다.
      임의의 자연어 질문에 답하는 추론은 이 페이지에 연결되어 있지 않습니다.       For demo stability this page serves the verified CQ results as static data. The free-form box only matches keywords from the ten questions above (e.g. ZHUA01, motor power, 7300, 6201, OHUA03) and jumps to the matching CQ. No live reasoning over arbitrary natural language is wired into this page.

      물어보면 어디까지 답하나 How far does an answer go

      질문 유형별 카탈로그에서 세 문항만 뽑았습니다. 값에서 문서로 되짚는 질문, 어느 문서에도 없는 지표를 만드는 질문, 그리고 답이 없는 것이 정답인 질문입니다.
      아래로 스크롤하면 질문이 뜨고, 조금 더 내리면 그 정답이 뜹니다.       Three questions out of the catalogue: one that walks a value back to its document, one that builds a metric no document contains, and one whose correct answer is nothing at all. Scroll to reveal each question, then its answer.

      정답은 챗봇이 낸 출력이 아닙니다. 사람이 쓴 SPARQL 을 그래프에 직접 돌려 받은 값입니다 — 같은 질문에 매번 다른 질의가 지어지면 어느 쪽이 틀렸는지 판단할 기준이 없어지기 때문입니다. These answers are not chatbot output. They come from hand-written SPARQL run directly against the graph — otherwise there is no fixed reference against which a differing answer could be judged wrong.
